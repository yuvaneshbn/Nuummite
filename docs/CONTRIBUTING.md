# Contributing to Nuummite

Thanks for helping improve Nuummite.

## Before You Start

- Read the [README](../README.md) and [CODE_OF_CONDUCT](../legal/CODE_OF_CONDUCT.md)
- Check whether your change already exists in the current branch
- Keep changes focused and easy to review

## Reporting Issues

- Use a clear title that describes the problem
- Include your OS, compiler, Qt version, and any relevant runtime details
- Add reproduction steps, expected behavior, and actual behavior
- Attach logs or screenshots when they help explain the issue

## Pull Requests

- Open one PR per feature, fix, or refactor
- Link the issue if one exists
- Describe what changed and why
- Mention any build, runtime, or compatibility impact

## Code Style

- Match the existing code style in the files you touch
- Keep real-time audio and network paths simple and predictable
- Avoid unnecessary churn in unrelated files
- Prefer clear names and small functions when practical

## Testing

- Build the project after your change
- Test the affected runtime path if possible
- Include notes about what you verified in your PR description

## Suggested Workflow

1. Fork or branch
2. Make a small, reviewable change
3. Build and test
4. Submit the PR with a concise summary

## Questions

If something is unclear, open an issue or discuss it in the PR before making a large change.
